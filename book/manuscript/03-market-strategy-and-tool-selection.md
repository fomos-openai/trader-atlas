# 第三章 市场、策略与工具选择

## 3.1 先选择可以学习的市场

首发市场不是由潜在收益决定，而由可观察性、合规性、成本透明度和个人运维能力共同决定。香港法域下，平台牌照与产品准入必须使用证监会最新官方信息核验；“在其他地区可访问”不等于适合香港居民，也不等于某资产可向零售客户提供。

数字资产现货适合第一条研究路线的原因是全天候数据、规则相对直接、无需借券和不含到期换月；缺点同样明显：场所分散、历史数据口径不一、稳定币与托管风险突出、交易成本和 API 语义变化快。因此样例保持 venue-neutral，只接受本地数据，并要求实际使用者将策略映射到计划使用的持牌场所。

## 3.2 为什么先做趋势轮动

一个好入门策略应能用一句话解释经济直觉，规则少，成交稀疏，失败可诊断。趋势轮动假设：价格趋势可能因信息扩散、行为惯性和风险管理流持续一段时间；当两个资产都不满足趋势条件时，现金比强行持仓更诚实。

它不是因为历史上“总能赚钱”而被选择，而是能暴露研究链路的关键问题：日线何时完成、参数如何冻结、波动率如何缩放、现金如何定义、切换成本如何计入、样本外失败后如何处理。即使最终策略被拒绝，这条路线仍能产出可复用的操作系统。

## 3.3 策略家族选择矩阵

可以从五个维度评估策略：边际解释、数据负担、执行负担、尾部风险、容量与合规。对 OPC 的建议顺序是：

1. 现货趋势与简单配置；
2. 第二个低相关的中低频策略；
3. 跨市场 ETF 与外汇换算；
4. 在独立风险预算下研究基差或资金费率；
5. 最后才考虑做空、杠杆、期权或结构化产品。

均值回归往往需要更准确的交易成本和入场时点；基差策略看似中性，却包含融资、保证金、强平、场所和稳定币风险；双币盈本质上含期权式收益结构，不能当作普通存款。复杂度不只来自代码，而来自损失分布中难以观察的状态。

## 3.4 一人公司的最小工具栈

首版选择 Python 3.12、uv 锁定依赖、pandas/NumPy 进行透明计算、Parquet 保存列式数据、DuckDB 做本地查询、pytest 验证不变量、MkDocs 发布知识库、ReportLab 生成小书。Git 是研究审计系统，不只是代码备份。

首版不采用大型回测平台。一个只有两个资产、周频、long-or-cash 的规则可以用小型透明引擎实现，任何权重和费用都能逐行检查。Vectorized 工具适合快速筛查，却也让数千次参数尝试变得过于容易；若使用，必须同步记录 trial count。事件驱动框架只有在订单状态和真实执行成为核心问题时才值得引入。

## 3.5 数据源与执行场所不是同一个概念

研究可以使用许可允许的历史数据，但任何 paper/live 结论都应以计划执行场所的规则复核。不同场所即使都写 `BTC/USD`，时区、K 线边界、最低金额、手续费、成交量和停机历史也可能不同。不要把多个交易所的价格序列静默拼接成一条“更长历史”。如果必须构造复合参考价，应明确它只用于信号或异常检测，而不是假设可成交价。

数据 manifest 至少记录 provider、venue、instrument、quote、bar interval、时区、下载时间、起止日期、行数和 SHA-256。原始数据保持不可变，清洗后数据必须能追溯到输入和转换版本。

## 3.6 什么时候升级工具

只有具体瓶颈出现才升级：

- 数据超过单机内存，再评估 Polars 或分区 Parquet，而不是预先建设数据湖；
- 策略需要真实订单状态，再引入事件驱动引擎；
- 多场所对账成为稳定负担，再拆分服务；
- 定时任务的失败恢复无法由单机进程满足，再评估编排系统。

“未来可能需要”不是增加基础设施的充分理由。OPC 的每个组件都会形成长期维护税。
