# 第六章 BTC/ETH 现货趋势轮动案例

## 6.1 规则冻结

案例每周在 UTC 周一决策，只使用此前已完成且可用的日线。对每个资产计算：

- 90 日动量：当前收盘价除以 90 日前收盘价减一；
- 趋势过滤：当前收盘价高于 200 日简单移动平均；
- 30 日实现波动率：日对数收益标准差乘以 365 的平方根。

资产只有在动量为正且通过趋势过滤时才合格。两者都合格则选择动量较高者；都不合格或数据不足则持现金。分数相同时保留当前持仓，空仓时使用固定顺序保证确定性。

目标风险资产权重为 `min(0.99, 0.15 / realized_vol)`，剩余为现金。目标权重绝对变化不足 5 个百分点（0.05）时不交易。规则不含止损、RSI、机器学习、盘中择时或多周期投票。

## 6.2 数据接口

CSV/Parquet 固定包含 `timestamp`、`symbol`、`open`、`high`、`low`、`close` 和 `volume`。`timestamp` 是每日 `00:00 UTC` 的 bar 起点；研究运行只在该日线已经完成并落入本地文件后进行。BTC 与 ETH 使用同一报价资产。验证器检查：

- 唯一的 symbol/timestamp；
- 时间可解析为 UTC 且严格按日连续；
- `low <= open/close <= high`，价格为正，成交量非负；
- 两资产具有共同区间并有至少 200 日预热；
- 每个决策只读取其时间戳之前的已完成日线。

真实行情不进入仓库。运行产物记录输入路径、symbol mapping、区间、行数与 SHA-256；数据供应方和取得时间由使用者在本地 provenance 记录中补充。合成 fixture 只用于 CI。

## 6.3 下一 bar 成交

信号在决策时刻生成，目标权重在下一根 bar 开盘形成假设成交。策略切换资产时先卖后买，两条腿分别计费。基础成本为手续费 10 bp 加非手续费摩擦 5 bp/side；压力场景为 25 与 40 bp/side。现金收益为零。

这种模型仍比真实执行简单。它没有盘口、部分成交和冲击，因此结论必须写成“在给定日频与成本假设下的研究结果”。进入真实资金前，需要目标场所更高频数据和独立执行验证。

## 6.4 CLI 工作流

第一步验证数据：

```text
uv run trader-atlas validate-data --data <path>
```

第二步运行研究：

```text
uv run trader-atlas research --config configs/btc-eth-spot-trend.yml --data <path>
```

第三步在新数据上生成本地意向：

```text
uv run trader-atlas paper --config configs/btc-eth-spot-trend.yml --data <path>
```

每次运行写入独立目录，包含配置快照、数据 manifest、metrics、equity、orders、audit 和 trial ledger。相同输入运行两次，除 run ID 与生成时间外的研究结果必须字节级一致。

## 6.5 基准与解释

案例输出比较现金、BTC buy-and-hold、ETH buy-and-hold 与 BTC/ETH 50/50 buy-and-hold。若要区分“信号贡献”与“单纯降低风险资产权重”，应在后续研究中预注册并新增同风险目标基准，不得在看过结果后临时挑选。

报告收益、波动、回撤、尾部、换手、成本、现金占比和资产贡献。若策略只在一个历史阶段胜出，结论应是脆弱而非有效。若样本外或 25/40 bp 成本压力下失败，将状态标记为 `rejected`，不在同一版本继续调参。

## 6.6 测试保护的不是代码风格

核心测试验证研究不变量：

- 改变未来数据不会改变过去信号；
- 成本提高不会增加净收益；
- 权重从不低于零或超过 99%；
- 输入顺序不影响结果；
- 重复、缺失、非法 OHLC 会失败；
- 同一输入的研究与 paper 信号一致；
- 任何数据异常都不会扩大风险。

这些测试比覆盖率百分比更重要。它们把研究诚信变成自动检查。
